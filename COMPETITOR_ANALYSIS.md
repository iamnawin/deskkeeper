# Competitor Analysis

## Competitive Landscape

DeskKeeper operates near several categories. It is not a direct competitor to any of them — it occupies a gap between them.

---

## Desktop / Computer-Use Agents

| Product | What it does | Gap vs DeskKeeper |
|---|---|---|
| Claude Computer Use | Controls desktop on behalf of user | Full autonomous agent — acts, not just watches |
| OpenAI Operator | Browser-level task automation | Browser-only, execution-focused |
| Manus | General-purpose AI agent | Autonomous action, cloud-dependent |
| UI-TARS | Visual desktop automation | Execution-first, no passive monitoring |
| ByteBot | Browser automation agent | Browser-only |
| Open Interpreter | Code execution + desktop control | Developer tool, not a continuity layer |

**Gap**: These tools execute tasks. DeskKeeper watches existing tasks.

---

## Browser Automation Tools

| Product | What it does | Gap vs DeskKeeper |
|---|---|---|
| Browser Use | LLM-driven browser automation | Browser-only, execution-focused |
| Browser agents (generic) | Tab/page automation | No desktop app visibility |
| Chrome automation tools | Script-driven browser control | Not reactive to live state |

**Gap**: Browser-only. DeskKeeper is cross-app and cross-screen. A Chrome extension will be a companion, not the core.

---

## RPA Tools

| Product | What it does | Gap vs DeskKeeper |
|---|---|---|
| UiPath | Enterprise-grade desktop automation | Complex, enterprise-first, not personal |
| Power Automate | Microsoft workflow automation | Workflow-first, not state-watching |
| Automation Anywhere | Business process automation | Scripted, not reactive monitoring |

**Gap**: RPA tools run predefined workflows. DeskKeeper monitors emergent work state in real time.

---

## Productivity / Task Tools

| Product | What it does | Gap vs DeskKeeper |
|---|---|---|
| Todoist | Task list management | You create tasks manually — DeskKeeper detects them |
| Notion | Documentation + tasks | Project management, not live monitoring |
| Motion | AI scheduling | Calendar-based, not window-state-based |
| Akiflow | Task inbox | Manual capture, not automatic detection |
| Raycast | Quick launcher + tools | Command palette, not a continuity layer |
| Alfred | macOS launcher | Search + workflows, not state watching |

**Gap**: These tools require the user to manage tasks manually. DeskKeeper watches work already in motion.

---

## Notification / Monitoring Tools

| Product | What it does | Gap vs DeskKeeper |
|---|---|---|
| Build/deploy notifications | CI/CD alerts | Single-pipeline, single-app |
| Uptime monitors | Service health alerts | Infrastructure only |
| App-specific webhooks | Per-service triggers | No cross-app view |

**Gap**: Siloed notifications from individual tools. DeskKeeper provides a unified cross-app attention layer.

---

## Where DeskKeeper Is Different

The unique position:

1. **Scope**: Watches open windows across all apps and terminals — not browser-only, not one service, not pre-scripted workflows.
2. **Privacy**: Local-first, user-selected monitoring. No cloud by default.
3. **Stance**: Observe and notify — never act autonomously in MVP.
4. **Model**: Continuity, not execution. Works with your existing workflow, not instead of it.
5. **Entry point**: Starts simple — window title + rule-based detection. No AI required.

The wedge: DeskKeeper does not start by doing tasks for the user. It starts by **remembering what the user is already doing.**
